# 하드웨어 연결 설정

이 문서는 좌수 Custom Hand의 미들웨어 패키지 설정과 `right_rl_with_mujoco/deploy`의 오른손 실기 기록을 정리합니다. 포트·게인·제한은 각 시험 환경의 값입니다. 통합 PC와 조립 상태에 맞는지는 별도로 확인합니다. Custom Hand 단독 시험은 기존 ROS 액션 서버에 연결한 실기 제어기를 사용합니다. 실행 조건과 절차는 [좌수 실기 실행 문서](custom-hand-hardware.md)에 있습니다.

## 2026-11-16 오른손 기록 반영

오른손 후속 실물 기록의 **COM7 / 1 Mbps / ID 1–16 / 모델 응답1240 / 펌웨어53 / 최신 관절 대응**을 반영했다.
기록은 원래 PC의 2026-11-09·13 조립 조건에서 얻은 것으로, 현재 middleware PC의 calibration 승인과 구분한다.
출처와 남은 연결 작업은 [오른손 상태](right-hand-status.md), 검사한 값·원본 해시는 [근거 JSON](evidence/right_hand_20261116.json)에 있다.

## Custom Hand 실기 설정과 확인 상태

아래 수치는 미들웨어 패키지의 [모터 설정](../src/control/custom_hand_control/config/config.provisional.json)과 [시험 보정값](../src/control/custom_hand_control/config/primitive_calibration.local.json)에서 확인했다. 접힘 기준은 정책 변환과 명령 제한에 사용하는 시험 설정이다. 기계적 한계는 별도로 검증해야 한다.

| 손가락 | 모터 ID | 초기 위치 (틱) | 접힘 기준 (틱) | 파지 판정 범위 (틱) | 대응 상태 |
|---|---:|---:|---:|---:|---|
| front | 1 | 1299 | 705 | 702–901 | 사용자 확인 |
| left | 2 | 2749 | 1800 | 1797–2428 | ID1 기준 왼쪽 사용자 확인 |
| back | 3 | 2378 | 1700 | 1697–1778 | 설정상 남은 모터로 추정, 실물 대응 재확인 필요 |
| right | 4 | 2292 | 1700 | 1697–1855 | ID1 기준 오른쪽 사용자 확인 |

정책 순서는 right/front/left/back = ID4/1/2/3이다. 모터 위치·속도 4개씩으로 관측을 만들고 정책 출력 4개를 매 주기 위치 목표로 변환한다. 엔코더 기반 파지 판정과 함께 큐브가 실제로 잡혔는지 확인한다.

### 손목 회전과 재파지

기준 2400틱에서 시계 방향은 틱 감소다. 보정 파일의 `min_tick`·`max_tick`은 352~3538틱이며, 기본 시험 모드는 보정된 회전 목표와 30틱 여유로 동작 범위를 계산한다. 이때 명령 목표 범위는 295~3538틱, 피드백 검사 범위는 265~3568틱이다. 회전 속도 레지스터는 550, 복귀 속도 레지스터는 600, 가속도는 10이다.

| 회전 요청 | 손목 구간 | 기준 위치에서의 최종 목표 | 회전 중 재파지 |
|---|---|---:|---|
| `1` | 시계 방향 50° + 45° | 1319틱 | 1구간 100틱, 2구간 50틱 |
| `-1` | 반시계 방향 50° + 50° | 3538틱 | 1구간 100틱, 2구간 50틱 |
| `2` | 시계 방향 47.5° + 47.5° + 45° + 45° | 295틱 | 처음 세 구간 각 75틱, 두 번째 구간 뒤 1초 유지 |

회전 중에는 손목 피드백의 진행률에 맞춰 손가락을 조인다. 각 회전의 마지막에는 50틱을 추가로 당기고 목표값을 읽어 확인한다. 해제는 손가락이 열린 뒤 손가락 토크 OFF를 확인하고, 손목을 기준 위치로 복귀시킨 다음 손목 토크를 끈다.

## LEAP Hand 후속 실물 관절 대응

아래 motor ID는 `hand_motor_mapping.py`와 11/13 실물 실행 기록의 최신 대응이다.
손끝→손바닥은 엄지1/2/3/4, 검지5/7/6/8, 중지9/11/10/12, 약지13/15/14/16이다.
시뮬레이션 좌표는 `qsim=(ticks-2048)*2π/4096`이며, 원본 정책 좌표·관측 계약과의 대조는 별도 수행한다.

오른손 촬영 기록에는 별도 USB `Streaming Webcam`, DSHOW, 1280×720 영상이 있다. middleware 인식 카메라와 동일 장치·동일 보정이라고 가정하지 않는다.
