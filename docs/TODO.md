# 실물 통합 작업 지시

Windows ROS 2 미들웨어는 카메라로 큐브를 인식하고 풀이를 생성하며, 두 손의 작업 순서를 dry-run합니다. 좌수 Custom Hand는 기존 ROS 액션 서버에 실기 제어기를 연결했습니다. 다음 작업은 이식한 좌수 패키지의 실물 시험과 두 손 통합에 필요한 센서·제어·정지 검증입니다.

### 2026-11-16 오른손 작업 재개 기준

2026-11-27: 최신 main의 좌수·설치·인터페이스 변경을 병합하고, 오른손 저장 경로 backend를 표준 `leap_hand_primitive_server`의 명시적 `hardware_enabled` 옵션에 연결했다. 기본 dry-run은 유지하며 G/가로/세로·현재 면 방향 요청과 G 유지·오류/취소/정지를 재사용한다. [오른손 실기 실행](leap-hardware.md). 실제 ROS/모터·양손 검증은 남아 있다.

- 원래 PC의 실물 기록은 [right-hand-status.md](right-hand-status.md)와 [근거 JSON](evidence/right_hand_20261116.json)에 반영했다. 이미 확보한 기록을 먼저 재사용하고, 새 PC·배선·조립으로 달라진 항목을 확인한다.
- 오른손 통신 기준은 **1Mbps**, 최신 관절 ID 대응을 사용한다. 기존 deploy의3Mbps·옛 SIM2ARR을 현재 실물 확정값으로 복사하지 않는다.
- 하드웨어 구현은 `feature/hardware`에서 진행하고 `apps/monitoring_ui`는 수정하지 않는다.
- 구현 순서는 설정 대조 → 단일 포트 소유 I/O·상태 발행 → 명령/완료/오류/취소 연결 → 오른손 지지 유지 계약 → 실물 검증이다. 경로 재생과 정책 추론 backend를 구분한다.

### 2026-11-16 통합 실행기 구현

- TODO6의 일부: 손 primitive 성공 응답 뒤에만 계획 상태·면 방향을 갱신하도록 수정했다. 오른손 요청에는 회전 전의 현재 면 방향을 전달한다.
- 손/정책 액션의 수락·완료 시간제한과 취소 확인을 연결했다. 시간초과·종료 불명확 상태는 다음 실행까지 차단한다.
- `pixi run check-execution-contract`로 장치 없는 순서·실패·취소 시험을 재현한다. 상세와 실제 ROS/실물에서 남은 항목은 [execution-contract.md](execution-contract.md)를 확인한다. 이 수정이 실제 모터 adapter 구현 완료를 뜻하지 않는다.

- 좌수 `develop/chu`에서 사용자가 CLI와 독립 ROS 서버의 파지·회전·해제를 실기 확인했다. [좌수 저장소 실기 문서](https://github.com/2026-HBNU-Capstone-Robot-Muscle/left-rl-with-mujoco/blob/develop/chu/docs/primitive_README.md)
- 미들웨어의 기존 서버에 제어기·실기 PPO·모터 설정·시험 보정값을 이식했다. Windows 빌드와 모터를 쓰지 않는 좌수 ROS 액션 및 두 손 풀이 경로를 검증했다. [좌수 실기 실행 문서](custom-hand-hardware.md)
- 다음은 이식한 패키지로 파지 유지, 세 회전 요청, 해제 후 손목 복귀와 토크 OFF를 실물에서 확인하는 작업이다. LEAP 실기 연동이 준비되면 두 손의 오류 처리와 재개 조건을 확인한다. [하드웨어 설정표](hardware-setting.md) · [미완료 항목](incomplete.md)

### 1. 실물과 연결 정보 확인

각 장치를 연결하기 전에 다음 정보를 docs/hardware-setting.md에 기록하세요.

- 사용한 USB 어댑터와 Windows COM 포트
- 장치별 통신 속도와 통신 프로토콜
- 모터별 응답 ID, 모델 번호, 펌웨어 버전
- 장치별 전원 공급 방식과 비상 정지 방법
- 검사 날짜, 담당자, 사용한 하드웨어 구성

포트와 모터 ID는 기존 코드의 후보값만으로 확정하지 말고, 현재 조립된 실물에서 응답을 확인하세요.

### 2. LEAP Hand 연결 및 매핑 확인

2026-11-16 구현: 실제 motor ID 순서를 적용한 ROS 상태 어댑터, READ-only SDK 연결, mock 동작 요청·완료·취소·지지 유지 계약을 추가했다. 원래 PC에서16개 모터 상태2회를 실제로 읽었고 쓰기·토크 변경은0회다. [leap-adapter.md](leap-adapter.md)에 실행법과 남은 실제 목표 전송 backend·ROS 검증을 정리했다.

right_rl_with_mujoco/deploy의 설정을 참고하되 실물에서 확인하세요.

- 모터 ID 1–16의 연결 여부와 모델 번호
- 각 ID와 실제 관절의 대응 관계
- 각 관절의 영점, 회전 방향, 실물에서 안전한 동작 범위
- 참조 코드에서 부호가 미확인으로 표시된 if_rot, mf_rot, rf_rot
- 실제 LEAP 모델과 참조 드라이버의 제어 테이블 및 단위 호환성
- 정책 입력 관측의 구성·순서·단위가 학습 시 설정과 일치하는지

처음에는 토크를 끈 상태에서 정보를 읽고, 이후에는 손가락별로 저위험 단일 관절 검증을 수행하세요. 모터 전체를 한꺼번에 움직이지 마세요.

2026-11-16 정책 연결부 개선: 물리 ID↔시뮬레이션 좌표 변환을 공통 모듈로 모으고, 잘못된 관측이 이력을 일부만 갱신하던 동작과 미전송 shadow 행동을 직전 실행 행동으로 재입력하던 동작을 수정했다. 중복·역순 표본, 새 실행·목표·데이터 공백 처리와 정상 입력128개·추론512개 비교를 포함해 소프트웨어59개 시험을 통과했다. 실제 ROS/모터 제어 검증과 구분한다. 상세는 [leap-policy-contract.md](leap-policy-contract.md)를 확인한다.

### 3. Custom Hand 손가락 확인

미들웨어에 설치된 `config.provisional.json`과 `primitive_calibration.local.json`을 참고해 현재 실물에서 확인하세요.

- 참조 설정인 COM8, 1 Mbps, ID 4·1·2·3이 현재 PC와 조립에서도 맞는지
- ID별 모델 번호와 손가락 대응
- 영점, 방향, 안전한 open/close 범위
- 전류·온도·추종 오차 한계와 정지 동작
- 정책 입력 8개와 출력 4개의 순서·단위가 실기 코드와 일치하는지

사용자가 참조 코드로 동작을 확인한 사실은 참고하되, 현재 middleware PC의 포트·매핑·안전 한계도 별도로 기록하세요.

### 4. Custom Hand 손목 모터 확인

기존 Custom Hand ROS 액션 서버에 STS3215 ID10 제어를 연결했다. 이식한 패키지에서 손목 회전·복귀와 정지 동작을 확인해야 한다.

- Feetech STS3215의 실제 COM 포트, 통신 속도, 프로토콜, 모터 ID
- 손목 회전축의 방향, 영점, 안전한 회전 범위
- 속도·가속도 제한과 작업 완료 확인 방법
- 통신 끊김·정지 요청·비상 정지 때의 동작

단독 시험의 결과를 기록한 뒤 두 손 통합 시험의 정지·완료 기준에 반영하세요.

### 5. 큐브 위치와 좌표계 연결

임시 배치 후 이동 예정이라는 사용자 조건을 반영해 배치별 프로필과 손목 기준 상대 좌표 후보를 추가했다. 임시 모드는 정책 pose를 발행하지 않는다. 이동 뒤 새 프로필 생성 시 외부 좌표와 색 면 축 검증을 비우고, 조건이 같은 내부 보정·마커 고정 변환은 재사용할 수 있게 했다. 전체 소프트웨어 시험100개 통과. 이동 자체의 자동 감지는 아니며 실제 카메라/좌표 확인은 남아 있다.

2026-11-16 입력부 구현: 마커 없는3×3 격자·중심색 다중 면 PnP와 손목 ID41의 센서 변환, 동일 노출 시각의 ROS 입력 연결을 추가했다. 초기6면 검사에서 중심색을 자동 전달한다. 좌표 등록 전에는 후보 토픽만 발행하고 정책용 pose는 차단한다. 소프트웨어 전체89개 시험 통과. 실물 보정·2면 격자 관측·YOLO/ROS 실제 실행 검증은 남아 있다. [markerless-pose.md](markerless-pose.md)에 실행과 저장 자료 결과를 정리했다.

큐브를 실제로 잡고 돌리려면 센서와 로봇의 좌표 관계가 필요합니다.

- 실제 사용하는 카메라와 보정 정보
- 큐브 pose를 제공하는 노드 및 ROS 토픽
- 로봇 기준 좌표계와 큐브·양손 기준 좌표계의 이름과 변환
- LEAP 손바닥과 Custom Hand의 큐브 기준 위치
- pose 갱신 주기와 오래되거나 유효하지 않은 pose를 판정하는 기준

현재 카메라 모델과 3D pose·좌표 변환은 확정되지 않았습니다. 영상의 YOLO 검출만으로 실제 3D 위치가 확인된 것으로 간주하지 마세요.

### 6. ROS2 정책 및 동작 연결

하드웨어 정보와 입력 계약을 확인한 뒤 다음을 middleware에 연결하세요.

- LEAP 정책에 들어가는 관측값의 출처, 순서, 단위, 시간 기준
- Custom Hand 정책 입력과 모터 상태 변환
- 양손 primitive가 실제 작업 순서와 맞는지
- 모터 명령 전송, 동작 완료 확인, 오류·취소·통신 단절 처리
- 각 단계가 완료되기 전에 다음 hand primitive로 넘어가지 않는지

모델 파일이 있다는 사실만으로 정책 입력과 실제 구동이 호환된다고 판단하지 말고, 실측 입력으로 shadow 결과를 먼저 비교하세요.

### 7. 안전 검증 및 단계별 실물 시험

실물 구동 전에 다음 항목을 설정하고 검증 기록을 남기세요.

- 비상 정지와 통신 끊김 시 정지 동작
- 모터별·손목별 안전 범위와 전류·속도 제한
- 단일 모터 시험 결과
- 손을 큐브에 접촉시키지 않는 무부하 시험 결과
- 큐브를 지지하고 한 동작만 수행하는 저속 시험 결과
- 실패 시 복구 방법과 담당자

검증을 완료한 항목만 hardware_calibration에 기록하고 검증 상태를 표시하세요. 임시값이나 시뮬레이션 범위를 검증된 실물 한계로 표시하지 마세요.

### 완료 기준

통합 완료로 판단하려면 팀원이 다음을 확인하고 기록해야 합니다.

1. 양손의 실제 포트·모터 ID·모델·관절 매핑이 확인됨
2. 정책 입력과 실측 상태의 순서·단위가 일치함
3. 큐브와 양손의 pose 및 좌표 변환이 연결됨
4. 손가락과 손목의 한계·정지 동작이 실물에서 검증됨
5. dry-run에서 실제 구동으로 전환한 ROS 경로가 오류·취소·완료를 처리함
6. 저위험 단위 시험부터 큐브 풀이 전체 실행까지 단계적으로 검증됨
7. 결과와 미완료 사항이 docs/hardware-setting.md, docs/incomplete.md에 기록됨

현재 문서의 확인된 설정과 미완료 항목은 [hardware-setting.md](hardware-setting.md)와 [incomplete.md](incomplete.md)에 있습니다.
