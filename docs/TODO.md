# 실물 통합 작업 지시

현재 ROS2 middleware는 Windows 환경에서 카메라로 큐브를 인식하고 풀이를 생성하며, ROS 액션으로 각 손의 작업 순서를 dry-run하는 단계까지 구현되어 있습니다. 다음은 실제 하드웨어 정보와 센서 입력을 확인해 연결하고, 안전 검증을 거쳐 실물 동작을 확인하는 작업입니다.

### 1. 실물과 연결 정보 확인

각 장치를 연결하기 전에 다음 정보를 docs/hardware-setting.md에 기록하세요.

- 사용한 USB 어댑터와 Windows COM 포트
- 장치별 통신 속도와 통신 프로토콜
- 모터별 응답 ID, 모델 번호, 펌웨어 버전
- 장치별 전원 공급 방식과 비상 정지 방법
- 검사 날짜, 담당자, 사용한 하드웨어 구성

포트와 모터 ID는 기존 코드의 후보값만으로 확정하지 말고, 현재 조립된 실물에서 응답을 확인하세요.

### 2. LEAP Hand 연결 및 매핑 확인

right_rl_with_mujoco/deploy의 설정을 참고하되 실물에서 확인하세요.

- 모터 ID 1–16의 연결 여부와 모델 번호
- 각 ID와 실제 관절의 대응 관계
- 각 관절의 영점, 회전 방향, 실물에서 안전한 동작 범위
- 참조 코드에서 부호가 미확인으로 표시된 if_rot, mf_rot, rf_rot
- 실제 LEAP 모델과 참조 드라이버의 제어 테이블 및 단위 호환성
- 정책 입력 관측의 구성·순서·단위가 학습 시 설정과 일치하는지

처음에는 토크를 끈 상태에서 정보를 읽고, 이후에는 손가락별로 저위험 단일 관절 검증을 수행하세요. 모터 전체를 한꺼번에 움직이지 마세요.

### 3. Custom Hand 손가락 확인

left-rl-with-mujoco/sim2real의 코드를 참고해 현재 실물에서 확인하세요.

- 참조 설정인 COM8, 1 Mbps, ID 4·1·2·3이 현재 PC와 조립에서도 맞는지
- ID별 모델 번호와 손가락 대응
- 영점, 방향, 안전한 open/close 범위
- 전류·온도·추종 오차 한계와 정지 동작
- 정책 입력 8개와 출력 4개의 순서·단위가 실기 코드와 일치하는지

사용자가 참조 코드로 동작을 확인한 사실은 참고하되, 현재 middleware PC의 포트·매핑·안전 한계도 별도로 기록하세요.

### 4. Custom Hand 손목 모터 확인

참조 실기 코드에서 손목 제어가 확인되지 않았으므로 별도로 조사하고 검증해야 합니다.

- Feetech STS3215의 실제 COM 포트, 통신 속도, 프로토콜, 모터 ID
- 손목 회전축의 방향, 영점, 안전한 회전 범위
- 속도·가속도 제한과 작업 완료 확인 방법
- 통신 끊김·정지 요청·비상 정지 때의 동작

이 정보와 안전 정지가 확인되기 전에는 middleware에 손목 구동을 연결하지 마세요.

### 5. 큐브 위치와 좌표계 연결

큐브를 실제로 잡고 돌리려면 센서와 로봇의 좌표 관계가 필요합니다.

- 실제 사용하는 카메라와 보정 정보
- 큐브 pose를 제공하는 노드 및 ROS 토픽
- 로봇 기준 좌표계와 큐브·양손 기준 좌표계의 이름과 변환
- LEAP 손바닥과 Custom Hand의 큐브 기준 위치
- pose 갱신 주기와 오래되거나 유효하지 않은 pose를 판정하는 기준

현재 카메라 모델과 3D pose·좌표 변환은 확정되지 않았습니다. 영상의 YOLO 검출만으로 실제 3D 위치가 확인된 것으로 간주하지 마세요.

### 6. ROS2 정책 및 동작 연결

하드웨어 정보와 입력 계약을 확인한 뒤 다음을 middleware에 연결하세요.

- LEAP 정책에 들어가는 관측값의 출처, 순서, 단위, 시간 기준
- Custom Hand 정책 입력과 모터 상태 변환
- 양손 primitive가 실제 작업 순서와 맞는지
- 모터 명령 전송, 동작 완료 확인, 오류·취소·통신 단절 처리
- 각 단계가 완료되기 전에 다음 hand primitive로 넘어가지 않는지

모델 파일이 있다는 사실만으로 정책 입력과 실제 구동이 호환된다고 판단하지 말고, 실측 입력으로 shadow 결과를 먼저 비교하세요.

### 7. 안전 검증 및 단계별 실물 시험

실물 구동 전에 다음 항목을 설정하고 검증 기록을 남기세요.

- 비상 정지와 통신 끊김 시 정지 동작
- 모터별·손목별 안전 범위와 전류·속도 제한
- 단일 모터 시험 결과
- 손을 큐브에 접촉시키지 않는 무부하 시험 결과
- 큐브를 지지하고 한 동작만 수행하는 저속 시험 결과
- 실패 시 복구 방법과 담당자

검증을 완료한 항목만 hardware_calibration에 기록하고 검증 상태를 표시하세요. 임시값이나 시뮬레이션 범위를 검증된 실물 한계로 표시하지 마세요.

### 완료 기준

통합 완료로 판단하려면 팀원이 다음을 확인하고 기록해야 합니다.

1. 양손의 실제 포트·모터 ID·모델·관절 매핑이 확인됨
2. 정책 입력과 실측 상태의 순서·단위가 일치함
3. 큐브와 양손의 pose 및 좌표 변환이 연결됨
4. 손가락과 손목의 한계·정지 동작이 실물에서 검증됨
5. dry-run에서 실제 구동으로 전환한 ROS 경로가 오류·취소·완료를 처리함
6. 저위험 단위 시험부터 큐브 풀이 전체 실행까지 단계적으로 검증됨
7. 결과와 미완료 사항이 docs/hardware-setting.md, docs/incomplete.md에 기록됨
