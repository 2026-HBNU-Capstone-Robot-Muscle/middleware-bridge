# LEAP 정책 입력과 shadow 실행 — 2026-11-16

공식 LEAP API/Sim/Isaac Lab에서 좌표 변환과 학습·배포 계약을 참고해 기존108차원 정책 연결부를 보완했다. 정책 가중치·알고리즘·관측의 유효 입력 계산식은 유지한다. 이 작업은 모터 출력이나 새 학습을 연결하지 않는다.

## 관절 좌표

`leap_hand_control/joint_mapping.py`가 관절 이름, 물리 ID 순서, 영점 변환을 관리한다. 실물 ID1~16 배열에서 MuJoCo 순서는 `(8,6,7,5,12,10,11,9,16,14,15,13,4,3,2,1)`이며 `qsim=(ticks-2048)*2π/4096`이다. 이름으로 받은 ROS 관절값은 같은 정책 순서로 재정렬한다. 중복·누락된 이름과 비정상 수치는 거부한다.

역변환 `physical_ticks`는 변환만 제공한다. 범위 승인, 자동 clipping, 모터 쓰기 기능은 없다. 공식 ID0~15 또는 다른 시뮬레이터의 관절 순서로 간주하지 않는다.

##108차원 관측

- 현재 관절16, 관절 오차 이력48, 손바닥-큐브 위치 오차 이력9, 자세 오차 이력18, 직전 행동16, 각도 오차1이다.
- 모든 벡터의 차원·유한성과 단위 쿼터니언을 먼저 확인한다. 입력을 거부하면 관절·위치 이력을 일부만 밀어 넣지 않는다.
- 실행 시작과 데이터 단절 후에는 기존 정책의 **0으로 채운 이력**을 유지한다. 공식 Lab96차원 정책의 초기화 방식으로 바꾸지 않았다.
- 같은 실행 안에서 목표 회전이 바뀌면 자세 오차 이력만 새 목표로 채운다. 쿼터니언 `q`와 `-q`는 같은 목표로 취급한다.

## 실행하지 않은 행동

기존 shadow 노드는 추론값을 전송하지 않은 상태에서도 `last_act`에 넣었다. 이제 `HandPolicyAction.shadow_only=True` 출력은 다음 관측의 직전 실행 행동으로 사용하지 않는다.

현재 `LeapPolicyInput`에는 적용된 정책 행동에 대한 확인 필드가 없으므로 shadow 관측의 `last_act`는0이다. 실제 Goal Position 레지스터에서 얻은 `commanded_joint_positions`는 계속 관절 추종 오차 계산에 사용한다. 이것만으로 실제 정책 행동의 적용량을 증명하지 않는다.

## 시간과 이력

입력·큐브·손바닥·인코더의 기존150ms 신선도 기준을 유지한다. 같은 실행에서 인코더 타임스탬프가 같거나 소스 시각이 역행하면 재추론과 이력 갱신을 하지 않는다. 거부된 입력, 새 실행, 긴 데이터 공백 뒤에는 관측 이력을 다시 시작한다. 추론이나 발행이 실패하면 해당 표본의 시각과 이력을 성공한 것으로 확정하지 않는다.

정책 입력 bridge가 검사하는 목표 레지스터 상태의 신선도도 계속 필요하다. ROS 시간 자체가 초기화되는 경우에는 실행 문맥을 새로 시작해야 한다.

## 확인한 것

`pixi run check-execution-contract` 또는 환경의 Python으로 `python scripts/check_execution_contract.py`를 실행한다. 이번59개 시험은 매핑 왕복, 중복·역순 입력, 새 목표·실행·공백 초기화, 실패 시 상태 보존, 기존 액션 실행기·READ-only 어댑터를 포함한다.

`tests/fixtures/leap_policy_reference.npz`는 수정 전의 정상 관측128개와 기존 정책 추론512개를 보존한다. 출처와 SHA256은 옆 JSON에 있다. 시험 허용 오차는 절대1e-12이며, 실패 처리를 개선하면서 정상 입력의 결과를 바꾸지 않았는지 비교한다. 기존 실제 구동 결합170개 원본은 변경하지 않는다.

## 남은 것

실제 ROS2 환경에서의 토픽·시간 연동, 카메라/손바닥 좌표 등록, 모터에 적용된 행동의 확인 계약,75ms 조건의 정책 동역학 평가는 별도 검증이 필요하다. 공식 PPO 체크포인트나96/102차원 입력을 현재108차원 정책에 직접 넣지 않는다.110차원 SAC 잔차 정책 연결이나 새 ADR 학습은 이번 변경에 포함하지 않았다. 실물 정책 제어는 활성화하지 않았다.
