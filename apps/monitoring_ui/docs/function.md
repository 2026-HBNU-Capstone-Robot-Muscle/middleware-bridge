# 모니터링 GUI 기능 정리

1. ROS2 연결 상태: rosbridge 주소와 연결 여부 표시
2. 실행 모드: 기본은 dry-run이며 `/cube/real_mode_ready` 신호가 유효할 때만 실물 모드 전환 가능
3. 큐브 인식·풀이 결과: 인식 상태, scan_id, 큐브 상태, 풀이 수열 표시
4. 3D 큐브 시각화: cube_3D_conversion의 구현을 참고해 큐브를 3D로 표시하고 풀이 과정을 미리보기
    - 토글로 관리
        - off(default): ROS 실행 피드백에 맞춰 3D 큐브와 진행 상태를 갱신
        - on: 실물과 별개로 GUI 상에서만 고정된 속도로 풀이 애니메이션 미리보기 실행.
    - 고정 속도 재생: GUI 애니메이션 속도는 사용자가 조절하지 않고 고정
    - off 상태에서의 큐브 시각화 갱신 단위: “오른손 회전 → 오른손 지지 → 왼손 회전”을 한 사이클로 보고, 사이클이 끝나면 큐브 상태와 풀이 진행을 갱신
5. ROS 브릿지 신호 모니터링 기능
    - 실행 제어: 선택한 풀이의 실행 요청과 취소
6. 실행 상태 표시: 현재 이동·단계·담당 손·완료·오류 표시
7. 실행 모드 표시: 현재 실행이 dry-run인지 실물 모드인지 GUI에서 명확히 표시
    - 기본값은 dry-run
    - `/cube/real_mode_ready` (`std_msgs/msg/Bool`)가 3초 이내 주기로 true를 보낼 때만 토글 활성화
    - readiness 신호는 실제 모터 연결, adapter, 보정, 안전 검증까지 완료했을 때만 true여야 함
    - 실물 실행 전 확인 대화상자 표시
    - readiness 신호 소실 시 토글 비활성화, 대기 중에는 dry-run으로 복귀, 실행 중에는 action 취소 요청
8. 이벤트 기록: ROS 연결, 풀이 수신, 실행 결과 기록

현재 executor와 hand primitive 서버는 `dry_run=false`를 거부하고 readiness publisher도 없으므로 토글은 비활성 상태가 기본입니다. GUI만의 토글로 실물 모터 구동을 활성화할 수 없습니다.
